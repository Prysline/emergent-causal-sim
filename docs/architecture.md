# v7.1 架構說明

## 分層

### `world.js`
只描述「世界裡有什麼」：資源種類、中文名稱、區域拓樸、角色、容器、來源、表面與初始數值。

角色狀態目前明確分成：

- `needs`：高值代表需求更迫切，例如飢餓、口渴、疲勞、社交、理毛需求。
- `wellbeing`：高值代表狀態較好，目前有舒適與安全感。
- `status`：效果型狀態，例如醉酒。

容器也分成物理能力與行為偏好：

- `canDrinkFrom`：物理上能否直接飲用。
- `drinkPreference`：角色通常有多偏好拿它來喝。

### `engine.js`
只處理「世界如何變化」：需求漂移、決策權重、多階段行動、移動、等待、物品持有、資源轉移、污染、攝入、醉酒、噪音與事件因果。它不直接操作 DOM。

v7.1 新增：

- Seeded PRNG：同 seed 可重跑。
- 飲用容器的 affordance / preference 分離。
- 人主動找貓與 `pendingInteraction` 回應流程。
- 有界因果事件保留。

### `ui.js`
只處理「如何看見世界」：地圖、目前行動、摘要時間線、完整時間線、Inspector 與手機分頁。它透過 `SimEngine` 讀取狀態並觸發 tick/reset。

v7.1 會明確顯示需求與正向狀態的方向差異、搬運資源、待回應互動與目前 Seed。

## UI 設計原則

1. 世界狀態優先於事件文字：先看地圖，再看 log。
2. 細緻行動不等於細碎畫面：目前行動用摘要卡，完整階段放到時間線完整模式。
3. 所有可識別 Entity 使用同一 Inspector 模式。
4. 物件名稱不決定用途；用途來自 affordance，角色偏好則是另一層。
5. Debug 因果保留完整的近期鏈條，但不讓歷史事件無限制佔用記憶體。
6. 可重現性是後續複雜系統的必要條件；任何奇怪連鎖都應能以 seed 重播。
